# 麦门营养参谋 · MCD Nutrition Coach

> 麦当劳 MCP 有 35 个接口，34 个在回答"怎么把东西卖给你"。
> 这个项目用剩下的那 1 个，回答"吃下去会怎样"。

一个基于**麦当劳中国官方 MCP** 的营养参谋 Skill：在下单之前，把这一餐的热量、蛋白质和钠算清楚。

不用改任何代码，配上 Token 就能用。**零第三方依赖**，只有 Python 标准库。

> 本项目是「2026 麦当劳程序员创意开发大赛」参赛作品，由参赛者独立开发，非麦当劳官方产品。

---

## 它解决什么问题

你在点餐页面看到的是**价格**，看不到**代价**。

随手点一份巨无霸 + 大薯条 + 大杯可乐，是 1116 kcal、1177 mg 钠。
你不会在屏幕上看到这两个数字，你的手机也不会告诉你——直到吃完。

这个 Skill 把这件事挪到下单之前：

```
$ python scripts/order_check.py --items "巨无霸*1,大薯条*1,可乐大杯*1"
====================================================================
麦门营养参谋 · 下单前体检  ⛔ 超标
====================================================================

餐品                         热量       蛋白       脂肪        钠
--------------------------------------------------------------------
巨无霸                       513       27       26      961
大薯条                       379        6       16      216
可乐大杯                      224        0        0        0
--------------------------------------------------------------------
合计                       1116       33       42     1177

⛔ 热量超标 366 kcal（1116 / 上限 750）
⛔ 钠超标 377 mg（1177 / 上限 800）

可以这样换（不牺牲蛋白质、只减热量）：
    · 可乐大杯 → 无糖可口可乐中杯：省 224 kcal，蛋白质 +0 g
    · 大薯条 → 麦乐鸡4块：省 209 kcal，蛋白质 +4 g
```

**三处替换省下 517 kcal，蛋白质一克没掉。**

它不劝你吃，也不劝你不吃。它只是把账算清楚，然后你自己决定。

## 两个核心能力

### 1. 下单前体检 —— 已经想好吃什么了

把清单丢进去，得到营养合计、参考线判定，以及**不牺牲蛋白质的替换建议**。

```bash
python scripts/order_check.py --items "巨无霸*1,大薯条*1,可乐大杯*1"
python scripts/order_check.py --items "麦辣鸡腿汉堡,大薯条" --kcal-max 700 --sodium-max 800
python scripts/order_check.py --items "板烧鸡腿堡*2,麦乐鸡5块" --json   # 结构化输出
```

支持口语叫法：「零度可乐」「甜筒」「薯条」「麦辣鸡腿堡」都会自动映射到菜单正式名。
（不做这层映射的话，"零度可乐"会被模糊匹配猜成普通可乐，一次就多算 147 kcal。）

### 2. 预算配餐 —— 还不知道吃什么

给它一个热量额度，它在真实菜单里求出**蛋白质最优**的组合。

```bash
# 午餐：主食 + 小食 + 饮品，650 kcal 以内，蛋白质至少 30 g
python scripts/meal_planner.py --slots main,side,drink --kcal-max 650 --protein-min 30 --top 5

# 早餐只要主食和饮品
python scripts/meal_planner.py --slots 早餐,drink --kcal-max 450

# 排除油炸
python scripts/meal_planner.py --slots main,side,drink --kcal-max 600 --exclude 薯条,脆汁鸡,V翅
```

输出示例：

```
【方案 1】✅ 达标  蛋白质密度 7.08 g/100kcal
    · 果然多肉                478 kcal   蛋白  36 g   脂肪  17 g   钠 1343 mg
    · 麦乐鸡4块               170 kcal   蛋白  10 g   脂肪  10 g   钠  337 mg
    · 锡兰红茶                  2 kcal   蛋白   0 g   脂肪   0 g   钠    0 mg
    合计：650 kcal | 蛋白 46 g | 脂肪 27 g | 碳水 55 g | 钠 1680 mg
    热量余额：0 kcal
    ⚠️ 钠 1680 mg，已超过一餐参考线 800 mg
```

同热量、同预算，配得好和配得差，蛋白质能差 15%。预算配餐的价值就是把这种差异显性化。

配餐目标可切换：

| `--objective` | 行为 |
|---|---|
| `fill`（默认） | 把预算吃满，不浪费额度，其次看蛋白质密度 |
| `density` | 纯追蛋白质密度，热量花在刀刃上 |
| `light` | 热量越低越好 |

## 快速开始

### 1. 申请麦当劳 MCP Token

前往 <https://open.mcd.cn/mcp>，手机号登录 → 右上角「控制台」→ 激活 → 复制 Token。

### 2. 配置 MCP

把 `mcp-config.example.json` 的内容加到你的 MCP 客户端配置里，把 `${MCD_MCP_TOKEN}` 换成你的 Token。

WorkBuddy 用户：左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】，
粘贴下面的 JSON 后保存并启用：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer 你的Token" }
    }
  }
}
```

> ⚠️ Token 是凭证，不要提交到任何仓库。本项目仓库内**不含任何真实 Token**。

### 3. 生成营养库

环境要求：Python 3.8+，无第三方依赖。

```bash
# 让 MCP 拉一次 list-nutrition-foods，把原始返回存到 data/raw/nutrition-raw.json
python scripts/parse_nutrition.py data/raw/nutrition-raw.json -o data/nutrition.json
```

> 仓库内已附带一份生成好的 `data/nutrition.json`（160 项），
> 不重新生成也能直接跑——这也是把数据落盘的好处之一：**离线可用**。

### 4. 开始用

```bash
python scripts/order_check.py --items "巨无霸*1,中薯条*1,可乐中杯*1"
python scripts/meal_planner.py --slots main,side,drink --kcal-max 650 --protein-min 30
python tests/test_smoke.py     # 16 项自测
```

作为 WorkBuddy Skill 使用时，`SKILL.md` 里定义了完整的对话工作流——
包括什么时候该先问清楚预算、什么时候必须提示钠超标、下单前必须确认哪些信息。

## 一个反直觉的发现

跑了上百组组合之后，最稳定的结论不是热量问题，而是**钠**：

麦当劳一份主食套餐的钠普遍落在 **1100–1700 mg**，而中国居民膳食指南建议
成人每日钠摄入低于 2000 mg——**一餐就吃掉了一半到八成以上**。

热量你还能靠"少吃点"控制，钠藏在里面，看不见。所以工具里把
"每餐钠超 800 mg 必须主动提示"写成了硬性规则，而不是可选建议。

## 设计取舍

**为什么营养计算放在本地，而不是每轮都问 MCP？**

1. 营养数据是静态的，一天拉一次足够，没必要每轮重打接口、白占限流额度；
2. 让大模型每次把 9 列 × 160 行的压缩文本重新对齐解析，是稳定的错行来源
   ——我们宁可解析一次、落成 JSON，也不接受"偶尔多算 300 kcal"；
3. 本地化之后可以离线跑、可以写单测。项目里 16 项自测全部覆盖解析对齐、
   别名映射、规格去重、约束求解、判定逻辑，就是这么来的。

**为什么坚持"不劝食也不劝不食"？**

因为一旦开始劝，工具就从参谋变成了推销员，或者变成了健身教练。
这两种角色都会让人不再相信它给出的数字。

## 数据来源与免责

- 营养数据来自麦当劳中国 MCP 的 `list-nutrition-foods` 接口，共 160 项餐品；
- 门店、在售、价格、优惠券信息均以麦当劳官方渠道当日实时结果为准；
- 参考线按成人每日 2000 kcal、钠 2000 mg 折算到单餐；
- 本项目输出为膳食搭配参考，**不构成医疗、营养或其他专业建议**；
  如有健康问题请咨询医生或临床营养师；
- 本项目仅使用麦当劳 MCP 公开接口，未做逆向、破解或其他非授权访问。
