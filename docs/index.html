35 个接口，只有 1 个在回答「吃下去会怎样」

麦当劳开放了 35 个 MCP 接口。其中 34 个在回答「怎么把东西卖给你」—— 下单、领券、算积分、查门店。只有 list-nutrition-foods 这一个，回答的是 「吃下去会怎样」。

这个项目只用那一个。它不劝你吃，也不劝你不吃——只是把账算清楚，然后你自己决定。

跑完上百组搭配，最普遍的问题不是热量，是钠

961 mg
一个巨无霸的钠含量，相当于《中国居民膳食指南》每日建议上限（2000 mg）的 48%。 一个汉堡就吃掉近一半。
59%
巨无霸 + 大薯条 + 大杯可乐合计 1177 mg 钠，一顿吃掉全天建议量的 59%。 而同一份套餐的钠，比它的热量更难在点餐页上看到。

所以这个 Skill 有一条硬性规则：每餐钠超过 800 mg 必须主动提示—— 不是等用户问，而是主动说。

30 秒跑一次，不用申请任何凭证

营养库（160 项真实餐品）已经随仓库落盘，不联网、不装包、不需要 Token 就能跑。只需要 Python 3.8+。 

$ git clone https://github.com/renxl1994/mcd-nutrition-coach.git
$ cd mcd-nutrition-coach
$ python scripts/order_check.py --items "巨无霸*1,大薯条*1,可乐大杯*1"
  1. 只是想看看效果 —— 上面三条命令就够了，零第三方依赖。
  2. 想当 Skill 用 —— 把整个文件夹放进 .workbuddy/skills/（或 ~/.claude/skills/）， AI 会自己读 SKILL.md 并自动触发，不用记任何命令。
  3. 想核对门店在售、真实价格并下单 —— 再去 open.mcd.cn/mcp 申请一个免费 Token，配进 MCP 即可。

它给出的建议，会自己标出代价

换法建议不是「省了多少热量」就完事。它给「把份量改小」和「钠变高」都标了价， 排序时一起权衡——否则很容易给出「热量降了但钠涨了 200 mg」这种自相矛盾的建议。

换成双层吉士汉堡 + 麦乐鸡 4 块 + 无糖可口可乐大杯： 热量 1116 → 599 kcal（-46%），蛋白质 33 → 37 g（还多 4 克）， 代价是钠 1177 → 1407 mg。工具会把这个代价一并打在建议后面，而不是替你藏起来。
